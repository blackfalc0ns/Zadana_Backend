# هاندوف تطبيق المندوب — التوزيع بالقرب (المنطقة الشرقية)

**الحالة:** مطبّق في الباك على فرع `feature/eastern-proximity-dispatch`  
**تاريخ:** 2026-08-21  
**الجمهور:** فريق تطبيق المندوب (Flutter / Mobile)  
**يُلغي / يحدّث:** أجزاء من `OPERATIONAL_GEOGRAPHY_HANDOFF_AR.md` اللي كانت تطلب اختيار مدينة (`DAMMAM` / `KHOBAR`…)

---

## 1) ماذا تغيّر في المنتج؟

المنطقة الشرقية (الدمام / الظهران / الخبر) بقت **مترو واحد للمندوبين**:

| قبل | بعد |
|-----|-----|
| المندوب مربوط بمدينة تسجيل | المندوب يختار **المنطقة الشرقية فقط** (`region = EASTERN`)، المدينة اختيارية/`null` |
| العروض تتقفل على تطابق اسم المدينة | العروض حسب **GPS حيّ ≤ 50 كم** من نقطة الاستلام (Haversine مستقيم، مش مسافة طريق) |
| `primaryZoneId` / اختيار zone | **ملغي** — استخدم `region` فقط |

**مهم:** الخرائط تفضل OSM/Leaflet للعرض. المطابقة **ما بتستدعيش** Nominatim ولا OSRM.

---

## 2) المطلوب من تطبيق المندوب (Checklist)

### أ) التسجيل + الملف الشخصي

- [ ] أخفِ قائمة **المدن** في التسجيل والبروفايل.
- [ ] اعرض منطقة واحدة ثابتة: **المنطقة الشرقية** / `EASTERN`.
- [ ] ابعت في التسجيل / تحديث المركبة:

```json
{
  "region": "EASTERN"
}
```

- [ ] **متبعتش** `city` (أو ابعتها `null`). لو ابعتها قديمة، السيرفر يخزّنها لكن **ما بيستخدمهاش** في التوزيع.
- [ ] **متبعتش** `primaryZoneId`.
- [ ] ناقص الجغرافيا في البروفايل = `missing_region` فقط (مش `missing_region_city` / `missing_zone_selection`).

مراجع العقود المحدّثة:

- `PROFILE_CONTRACT.md`
- `HOME_CONTRACT.md` (حقل `region` في `operationalStatus`)

Endpoints:

- `GET /api/drivers/me/profile`
- `PUT /api/drivers/me/profile/vehicle` ← جسم فيه `region: "EASTERN"` بدون مدينة
- `GET /api/geography/driver/regions` (لو محتاج قائمة مناطق تشغيل — الشرقية فقط)

### ب) الموقع (GPS) — شرط استلام العروض

- [ ] أثناء **متاح / أونلاين**: ابعت موقع المندوب بانتظام عبر `POST /api/drivers/location`.
- [ ] السيرفر يشترط GPS **طازج** (حوالي **5 دقائق**) + مسافة ≤ **50 كم** من فرع الاستلام.
- [ ] لو الموقع قديم أو أبعد من 50 كم → المندوب **مش هيظهر** في التوزيع ومش هيقبل العرض عند الـ accept.
- [ ] عند رفض القبول لقرب خاطئ: رسائل/أكواد قرب (legacy code قد يظهر `DRIVER_CITY_MISMATCH` لكن المعنى = mismatch قرب، مش مدينة).

### ج) الهوم + العروض

- [ ] مصدر الشاشة: `GET /api/drivers/home` — متغيّرش منطق `homeState`.
- [ ] العروض اللي توصل المندوب أصلًا متفلترة قربًا من السيرفر؛ متفلترش محليًا باسم مدينة الفرع.
- [ ] `PUT /api/drivers/me/zone` = **legacy**؛ متربطهوش بتدفق الشرقية. حدّث المنطقة عبر بروفايل المركبة `region`.

### د) العملة والعرض

- [ ] كل المبالغ **ريال سعودي (ر.س / SAR)** — مفيش جنيه/EGP.

---

## 3) قواعد الباك باختصار (للموبايل)

```
متاح + Approved
+ region = EASTERN
+ آخر GPS خلال ~5 دقائق
+ المسافة للـ pickup ≤ 50 كم
→ يقدر يستلم / يقبل عرض
```

- قبول العرض (`POST /api/drivers/offers/{id}/accept`) يعيد فحص القرب.
- مناديب `city: null` **مسموح** ومطلوب للتسجيل الجديد.

---

## 4) أمثلة سريعة

### بروفايل (جزء جغرافي)

```json
{
  "region": "EASTERN",
  "city": null,
  "regionNameAr": "المنطقة الشرقية",
  "regionNameEn": "Eastern Region",
  "cityNameAr": null,
  "cityNameEn": null,
  "missingRequirements": []
}
```

### تحديث مركبة

```http
PUT /api/drivers/me/profile/vehicle
Authorization: Bearer <token>
Content-Type: application/json

{
  "vehicleType": "Motorcycle",
  "nationalId": "1xxxxxxxxxxxx",
  "licenseNumber": "DRV-1001",
  "region": "EASTERN"
}
```

### إرسال موقع

```http
POST /api/drivers/location
Authorization: Bearer <token>

{
  "latitude": 26.3927,
  "longitude": 50.1135,
  "accuracyMeters": 12
}
```

(استخدم حقول الـ body الفعلية كما في عقد الموقع الحالي — المهم إحداثيات حديثة ودورية.)

## 5) اختبار يدوي مقترح

1. سجّل مندوب بمنطقة شرقية **بدون مدينة** → يكمّل البروفايل بدون `missing_region`.
2. ابقَ أونلاين مع GPS في الدمام → لازم يقدر يستلم عرض استلام في الخبر لو ≤ 50 كم.
3. أوقف تحديث الموقع > 5 دقائق → العروض تختفي / القبول يفشل.
4. اطلع أبعد من 50 كم عن الـ pickup → مفيش عرض / قبول مرفوض.
5. تأكد إن مفيش UI لمدن التشغيل ولا zones قديمة.
