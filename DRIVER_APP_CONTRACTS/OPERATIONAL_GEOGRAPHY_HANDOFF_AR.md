# تغييرات الموبايل - نطاق التشغيل الجغرافي للمندوب

## الحالة

- `implemented`
- تاريخ التحديث: 2026-07-09

## الخلاصة

نطاق تشغيل المندوب والتاجر حاليًا مقفول على:

- المنطقة: `EASTERN`
- الاسم العربي: `المنطقة الشرقية`
- المدن: مدن المنطقة الشرقية التي فيها متجر/فرع متاح فعليًا للمندوب

هذا التقييد خاص بمنطقة التشغيل للمندوب/التاجر فقط. عناوين العملاء أو المستخدمين العاديين لا تتغير، وتظل قادرة على استخدام قائمة مناطق ومدن السعودية كاملة حسب شاشة العميل.

## ما المطلوب من تطبيق المندوب؟

### 1. شاشة تسجيل المندوب

لو شاشة التسجيل فيها اختيار منطقة ومدينة التشغيل:

- اعرض منطقة واحدة فقط: `EASTERN`
- اعرض المدن من API مدن تسجيل المندوب فقط
- خزّن وأرسل `code` وليس الاسم المعروض

القيم التي يجب إرسالها:

```json
{
  "region": "EASTERN",
  "city": "DAMMAM"
}
```

مثال: لو المستخدم اختار الدمام، أرسل `DAMMAM` وليس `الدمام`.

### 2. شاشة تعديل ملف المندوب

لو تطبيق المندوب يسمح بتعديل بيانات المركبة/منطقة التشغيل من الملف الشخصي:

- لا تعرض كل مناطق السعودية
- لا تسمح بإرسال منطقة غير `EASTERN`
- عند تغيير المدينة، لازم تكون من مدن الشرقية التي فيها متجر/فرع متاح

Endpoint المتأثر:

- `PUT /api/drivers/me/profile/vehicle`

الحقول المتأثرة:

- `region`
- `city`

### 3. شاشة مراجعة أو استكمال بيانات المندوب

أي شاشة onboarding أو profile completion فيها `region/city` لازم تتبع نفس القاعدة:

- `region = EASTERN`
- `city` من مدن تسجيل المندوب المتاحة

## APIs المطلوبة للموبايل

### تحميل المنطقة التشغيلية

لا تحتاج لتحميل كل المناطق من أجل المندوب. يمكن تثبيت المنطقة في التطبيق:

```json
{
  "code": "EASTERN",
  "nameAr": "المنطقة الشرقية",
  "nameEn": "Eastern Region"
}
```

ولو التطبيق عنده component عام يحتاج API، يمكن استخدام:

- `GET /api/geography/regions`

ثم فلترة النتيجة محليًا على:

- `code == "EASTERN"`

### تحميل مدن تسجيل المندوب

استخدم:

```http
GET /api/geography/driver/regions/EASTERN/cities
```

الاستجابة تكون قائمة المدن التي فيها تاجر `Active` يستقبل طلبات وعنده فرع `Active`. استخدم:

- `code` كقيمة مرسلة للباك
- `nameAr` أو `nameEn` للعرض حسب لغة التطبيق

لا تستخدم endpoint المدن العام في تسجيل المندوب:

```http
GET /api/geography/regions/EASTERN/cities
```

لأنه يرجع كل مدن الشرقية حتى المدن التي لا يوجد فيها تجار متاحون.

مثال مختصر:

```json
[
  {
    "regionCode": "EASTERN",
    "code": "DAMMAM",
    "nameAr": "الدمام",
    "nameEn": "Dammam"
  },
  {
    "regionCode": "EASTERN",
    "code": "KHOBAR",
    "nameAr": "الخبر",
    "nameEn": "Al Khobar"
  }
]
```

## أخطاء الباك الجديدة

لو التطبيق أرسل منطقة خارج الشرقية:

```json
{
  "code": "UNSUPPORTED_OPERATIONAL_REGION",
  "message": "حاليًا التشغيل متاح في المنطقة الشرقية بس."
}
```

لو التطبيق أرسل مدينة غير تابعة للشرقية:

```json
{
  "code": "UNSUPPORTED_OPERATIONAL_CITY",
  "message": "لازم تختار مدينة من مدن المنطقة الشرقية."
}
```

لو التطبيق أرسل مدينة شرقية لكن لا يوجد فيها متجر/فرع متاح حاليًا:

```json
{
  "code": "DRIVER_CITY_HAS_NO_ACTIVE_VENDOR",
  "message": "المدينة هذي ما فيها متاجر متاحة حاليًا. اختر مدينة ثانية من المدن المدعومة."
}
```

لو المنطقة أو المدينة ناقصة:

- `SERVICE_REGION_REQUIRED`
- `SERVICE_CITY_REQUIRED`
- وقد يظهر في بعض endpoints القديمة: `DRIVER_SERVICE_AREA_REQUIRED`

الرسائل المعتمدة باللهجة السعودية:

- `SERVICE_REGION_REQUIRED`: `لازم تختار منطقة التشغيل.`
- `SERVICE_CITY_REQUIRED`: `لازم تختار مدينة التشغيل.`
- `DRIVER_SERVICE_AREA_REQUIRED`: `لازم تختار منطقة ومدينة التشغيل للمندوب.`

## سلوك واجهة المستخدم المقترح

### اختيار المنطقة

الأفضل في المرحلة الحالية:

- لا تعرض dropdown للمناطق لو مفيش غير الشرقية
- اعرضها كقيمة ثابتة أو disabled field:
  - عربي: `المنطقة الشرقية`
  - إنجليزي: `Eastern Region`

### اختيار المدينة

اعرض dropdown/searchable list للمدن القادمة من:

```http
GET /api/geography/driver/regions/EASTERN/cities
```

عند الحفظ أرسل:

```json
{
  "region": "EASTERN",
  "city": "<selected city code>"
}
```

## ما الذي لا يتغير؟

- لا تغير اختيار مدينة العميل في تطبيق العميل.
- لا تقفل عناوين العملاء على الشرقية من الموبايل.
- لا تغير تتبع الطلب أو تفاصيل المهمة.
- لا تغير إرسال موقع GPS للمندوب.
- لا تغير منطق العروض أو قبول/رفض الطلبات.

## Checklist لمبرمج الموبايل

- شاشة تسجيل المندوب تستخدم `EASTERN` فقط.
- شاشة تعديل بيانات المندوب تستخدم `EASTERN` فقط.
- المدن تأتي من `GET /api/geography/driver/regions/EASTERN/cities`.
- يتم إرسال `city.code` وليس `city.nameAr`.
- يتم التعامل مع `UNSUPPORTED_OPERATIONAL_REGION`.
- يتم التعامل مع `UNSUPPORTED_OPERATIONAL_CITY`.
- يتم التعامل مع `DRIVER_CITY_HAS_NO_ACTIVE_VENDOR`.
- لا يتم تعديل شاشات عناوين العملاء.

## Backend source of truth

الباك الآن يرفض أي منطقة/مدينة تشغيل خارج الشرقية في:

- تسجيل التاجر
- تحديث بيانات التاجر التشغيلية
- إنشاء وتعديل فروع التاجر
- تسجيل المندوب
- تحديث منطقة تشغيل المندوب من الأدمن
- تحديث منطقة تشغيل المندوب من تطبيق المندوب

بالنسبة للمندوب تحديدًا، الباك يرفض أي مدينة لا يوجد فيها تاجر `Active` يستقبل طلبات وعنده فرع `Active`.
