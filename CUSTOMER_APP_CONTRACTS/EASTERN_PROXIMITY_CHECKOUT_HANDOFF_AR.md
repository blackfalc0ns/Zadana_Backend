# هاندوف تطبيق العميل — أقرب فرع + توصيل ≤ 50 كم (المنطقة الشرقية)

**الحالة:** مطبّق في الباك على فرع `feature/eastern-proximity-dispatch`  
**تاريخ:** 2026-08-21  
**الجمهور:** فريق تطبيق العميل (Flutter / Mobile)  
**يحدّث سلوك:** اختيار فرع التوصيل / قابلية التوصيل / فروع الاستلام (Pickup) عند وجود إحداثيات  
**مرجع قديم:** `CHECKOUT_PICKUP_BRANCHES_BY_CITY_MOBILE_HANDOFF_AR.md` (كان مدينة-أولًا) — السلوك الجديد أدناه له الأولوية عند وجود lat/lng.

---

## 1) ماذا تغيّر في المنتج؟

| قبل | بعد |
|-----|-----|
| اختيار الفرع يفضّل نفس مدينة العميل | أقرب فرع للعميل بمسافة مستقيمة ≤ **50 كم** |
| نفس المدينة يتجاوز فحص نصف القطر | نفس المدينة **ما بتخطّيش** حد الـ 50 كم |
| عنوان بمدينة بدون إحداثيات ممكن يرتبط بفرع أساسي بعيد | بدون lat/lng صالحين → **مفيش ربط فرع تلقائي** (ما ينفعش توصيل بالمسافة) |
| فلترة فروع الاستلام بالمدينة فقط | لو العنوان فيه إحداثيات → فلترة/ترتيب **بالقرب** (≤ 50 كم) |

**مهم:**

- المطابقة Haversine (خط مستقيم) — **مش** مسافة طريق OSRM.
- عناوين العملاء تفضل تقدر تستخدم جغرافيا السعودية كاملة؛ التقييد الشرقي خاص بـ **تشغيل المندوب/التاجر** مش بقفل عنوان العميل.
- العملة المعروضة: **ر.س / SAR**.

## 2) المطلوب من تطبيق العميل (Checklist)

### أ) عناوين التوصيل — إحداثيات إلزامية عمليًا

- [ ] عند حفظ/اختيار عنوان توصيل، خزّن وأرسل **`latitude` + `longitude`** صالحين (من الخريطة / GPS / geocoder عند الإنشاء).
- [ ] لو العنوان **مدينة فقط** بدون إحداثيات:
  - السيرفر **مش هيختار** فرع توصيل تلقائيًا.
  - اعتبر الحالة غير قابلة للتوصيل بالمسافة → وضّح للمستخدم يحدد الموقع على الخريطة.
- [ ] مت依赖ش على تطابق اسم المدينة وحدها عشان تقول "في نطاق التوصيل".

### ب) السلة / Checkout / التوصيل (Delivery)

- [ ] خلاصة الشيك أوت (`GET /api/checkout/summary` أو المسار الحالي عندكم) تعتمد على عنوان فيه إحداثيات.
- [ ] الفرع اللي بيتعمل عليه الطلب = **أقرب فرع** ضمن 50 كم (السيرفر يختار؛ الموبايل يعرض النتيجة/الأخطاء).
- [ ] لو المسافة > 50 كم → حالة undeliverable / المتجر غير متاح للعنوان — اعرض رسالة السيرفر كما هي.
- [ ] **متكسرش** نفس-المدينة كاستثناء يتجاوز الـ 50 كم في الـ UI.

### ج) الاستلام من الفرع (Pickup)

- [ ] استمر في إرسال `vendor_branch_id` بعد اختيار الفرع (زي العقد القديم).
- [ ] عند استدعاء فروع الاستلام مع `address_id` فيه إحداثيات: توقّع قائمة مرتبة/مفلترة **بالقرب** مش مدينة فقط.
- [ ] لو لسه بتبعت `city` بدون عنوان بإحداثيات: السلوك القديم المبني على المدينة ممكن يفضل، لكن للإطلاق الشرقي **فضّل address_id بإحداثيات**.

Endpoint مرجعي:

```http
GET /api/checkout/pickup-branches?vendor_id={vendorId}&address_id={addressId}
```

أو مع `city` (أضعف بدون إحداثيات).

### د) الخرائط والعرض

- [ ] خريطة اختيار العنوان: افتراضي منطقي للمنطقة الشرقية عند الإطلاق (مثل الدمام) لو المستخدم جديد هناك — اختياري UX.
- [ ] اعرض المسافات/الرسوم بالريال **SAR / ر.س** فقط.
- [ ] متستخدمش OSRM عام لمسار المطابقة؛ لو عايزين مسار على الخريطة للعرض فقط، ده منفصل عن قرار التوصيل.

---

## 3) قواعد الباك باختصار

```
عنوان فيه lat/lng
→ أقرب فرع للتاجر ضمن 50 كم
→ لو مفيش فرع ضمن 50 كم = غير قابل للتوصيل

عنوان بدون lat/lng
→ لا ربط فرع تلقائي بالمسافة
```

تسعير التوصيل الحي يعتمد على أقرب مندوب GPS طازج ضمن 50 كم (حتى لو `city` عند المندوب null) — الموبايل يعرض الرقم اللي راجع من السيرفر.

---

## 4) أخطاء / حالات لازم تتعامل معاها في UI

| حالة | سلوك مقترح في الموبايل |
|------|-------------------------|
| عنوان بدون إحداثيات | اطلب تحديد الموقع على الخريطة قبل إكمال الطلب |
| كل الفروع أبعد من 50 كم | رسالة undeliverable من السيرفر + اقتراح عنوان أقرب أو Pickup إن متاح |
| `pickup_branch_required` | المستخدم لازم يختار فرع استلام (`vendor_branch_id`) |
| `PICKUP_CITY_REQUIRED` | لو استدعيت فروع الاستلام بدون city ولا address_id |

---

## 5) اختبار يدوي مقترح

1. عنوان في الدمام بإحداثيات + فرع في الخبر ≤ 50 كم → يختار أقرب فرع ويكمّل.
2. عنوان بإحداثيات أبعد من 50 كم عن كل الفروع → undeliverable.
3. عنوان مدينة فقط بدون lat/lng → مفيش فرع تلقائي؛ التطبيق يطلب موقع.
4. نفس المدينة لكن المسافة > 50 كم → **مرفوض** (مش مسموح بالتجاوز).
5. Pickup مع `address_id` بإحداثيات → فروع قريبة تظهر أولًا.
6. تأكد إن المبالغ SAR.
