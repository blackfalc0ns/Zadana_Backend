# Cart & Checkout Latest Updates

## Summary

This file summarizes the latest backend changes related to cart, checkout, delivery validation, and delivery ETA.

## Main Changes

### 1. Early delivery gate in cart

- Added a dedicated pre-check endpoint:
  - `GET /api/cart/delivery-check?vendor_id={vendorId}&address_id={addressId}`
- Purpose:
  - validate deliverability before entering checkout
  - return a clear delivery status for the selected address
  - prevent user frustration from discovering delivery issues too late

### 2. Unified delivery decision in checkout

- `checkout summary` now returns:
  - `delivery_check`
  - `estimated_delivery_window`
- `delivery_check` is now the source of truth for:
  - whether delivery is possible
  - whether checkout can continue
  - what message should be shown to the user

### 3. Checkout blocking when delivery is invalid

- If delivery is not valid for the selected address:
  - checkout remains readable
  - shipping cost is not treated as a valid proceed signal
  - client must block continue-to-checkout / place-order flow
- Server-side protection was also added so the order cannot be placed if delivery is not valid.

### 4. Realistic ETA window

- Checkout no longer relies on a fake exact ETA.
- It now returns `estimated_delivery_window` like:
  - `30-45 minutes`
  - `45-60 minutes`
- This ETA is generated by backend policy and should be rendered directly by the client.

### 5. ETA operational calibration

- ETA is now calibrated from operational data:
  - branch historical delivered orders first
  - vendor historical data as fallback
  - default policy if there is not enough data
- Calculation uses:
  - vendor preparation time
  - delivery distances
  - historical preparation / dispatch / last-mile behavior
  - operational buffer

### 6. Tracking ETA refinement

- Order tracking now uses the same ETA policy family.
- ETA becomes more accurate as the order moves through statuses:
  - accepted
  - preparing
  - ready for pickup
  - driver assigned
  - picked up
  - on the way

### 7. Vendor operations ETA health

- Vendor dashboard now exposes operational ETA health signals:
  - on-time rate
  - average delivery time
  - average preparation time
  - average dispatch lead time
  - average last-mile time
  - sample size
  - calibration source

## Key Endpoints

- `GET /api/cart/delivery-check`
- `GET /api/checkout/summary`
- `POST /api/checkout/place-order`
- `GET /api/orders/{orderId}/tracking`

## Frontend Rules

- Do not calculate delivery eligibility locally.
- Do not calculate ETA locally.
- Use `delivery_check` as the decision gate.
- Use `estimated_delivery_window.title`, `estimated_delivery_window.label`, and `estimated_delivery_window.subtitle` as the displayed checkout ETA block.
- Use tracking response as the source of truth after order placement.
